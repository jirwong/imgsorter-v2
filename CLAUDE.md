# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Quick Commands

### Build & Development

- **`pnpm build`** - Compile TypeScript to JavaScript with esbuild
- **`pnpm dev`** - Run the TypeScript entry point with tsx
- **`pnpm dev:watch`** - Watch src directory and rebuild/rerun on changes using tsx watch

### Type Checking & Linting

- **`pnpm typecheck`** - Type-check without emitting code (using tsc)
- **`pnpm lint`** - Run oxlint on src directory
- **`pnpm lint:fix`** - Run oxlint with auto-fix enabled

### Testing

- **`pnpm test`** - Run tests once with Vitest
- **`pnpm test:watch`** - Run tests in watch mode with Vitest

### Formatting

- **`pnpm format`** - Format all code using Prettier
- **`pnpm format:check`** - Check code formatting without making changes

## Project Structure

This project is a file-indexing and duplicate-detection utility (migrated from `imgsorter-utils` onto a modern TypeScript template):

- **`src/`** - All TypeScript source files live here
  - `index.ts` - CLI entry point
  - `runner.ts` - Runner orchestration class (also usable as a library)
  - `services/` - `db-service.ts` (SQLite) and `file-service.ts` (file listing/hashing)
  - `types/` - `configuration.ts` and `file-types.ts`
  - `utilities/` - `load-config.ts` (Zod-validated YAML config loader)
- **`config.yaml`** - User configuration (db name, extensions, directories, flags)
- **`dist/`** - Compiled JavaScript output (generated by `pnpm build`)
- **`tsconfig.json`** - TypeScript compiler configuration with strict mode enabled
- **`package.json`** - Node.js project metadata and dependencies
- **`.node-version`** - Node version for nodenv (v24.12.0)
- **`.nvmrc`** - Node version for NVM (v24.12.0)

## Development Notes

### Setup

- **Node.js 24.12.0** is required (specified in `.node-version` and `.nvmrc` for version managers)
- TypeScript strict mode is enabled, so all files must have proper type annotations
- Source code should be written in the `src/` directory with `.ts` extension
- Pre-commit hooks are configured with Lefthook:
  - Runs oxlint and Prettier on staged TypeScript files
  - Run `pnpm prepare` to install hooks (automatically run on `npm install`)

### Build & Development Workflow

- **esbuild** is used to compile TypeScript and bundle for Node.js platform
- **tsx** watches the `src` directory for changes and automatically rebuilds and reruns
- Use `pnpm dev` to run the TypeScript entry point
- Use `pnpm dev:watch` for fast iteration with auto-rebuild and auto-rerun (recommended for development)
- Use `pnpm build` before deployment or when you need compiled JavaScript output in `./dist`

### Testing & Linting

- Use `pnpm test:watch` during development for test-driven development
- Use `pnpm lint` to check for code issues before committing
- Use `pnpm build` before deployment or when you need compiled JavaScript output
- Use `pnpm typecheck` to verify type safety without building

## Git Commits

- Keep commit messages short and focused — one logical change per commit
- Use the imperative mood for the subject line (e.g. `Add feature`, `Fix bug`, `Remove unused dep`)
- Subject line should be 50 characters or fewer
- If more context is needed, add a blank line followed by a body (wrap at 72 characters)
- Commits should follow the Conventional Commits convention

## Code Formatting

Prettier is configured for consistent code formatting:

- Configuration is in `prettier.config.mjs`
- Run `pnpm format` to format all files
- Run `pnpm format:check` to verify formatting without changes
- Files in `.prettierignore` are excluded from formatting
